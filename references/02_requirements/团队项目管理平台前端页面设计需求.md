# 团队项目管理平台前端页面设计需求说明

> 这份文档给前端页面设计同学使用。  
> 目标不是让大家先写代码，而是先把页面样子、功能入口、信息展示方式设计清楚。  
> 设计时请尽量做到：清楚、简洁、好看、容易上手，手机和电脑都能用。

---

## 1. 项目整体定位

这个平台是团队以后长期使用的主页和管理系统，不只是一个普通表格工具。

它要解决的问题是：

- 团队项目太多，大家不知道项目现在进展到哪里；
- 比赛节点太多，容易忘记报名、提交、答辩、网评时间；
- 人员多，谁负责什么、谁最近有没有时间不清楚；
- 经费、奖金、票据、支出需要公开透明；
- 成员的贡献、任务、个人项目、比赛成果需要被记录；
- 软著、专利申请过程中，谁写的、谁申请的、谁修改的需要有依据；
- 团队需要一个对外展示成果的主页。

这个平台最后希望达到的效果：

> 让团队内部的信息公开透明，让每个人的努力都能被看见，让项目进度、任务分工、经费使用、成果申请都有记录、有依据、可追踪。

---

## 2. 前端设计总体要求

### 2.1 页面风格

建议整体风格：

- 简洁；
- 清爽；
- 有科技感；
- 不要太花；
- 不要像普通 Excel；
- 要有“团队管理驾驶舱”的感觉；
- 适合学生团队、科研团队、竞赛团队长期使用。

### 2.2 颜色建议

建议主色使用：

- 蓝色 / 科技蓝 / 深蓝；
- 辅助色可以用浅蓝、绿色、橙色、紫色；
- 警告信息用橙色；
- 逾期、异常、风险用红色；
- 已完成、正常状态用绿色；
- 草稿、待审核、处理中用灰色或黄色。

颜色不要太杂，每个页面最好保持统一。

### 2.3 字体与排版

要求：

- 文字清楚，不要太小；
- 标题层级明显；
- 表格不要太挤；
- 页面留白要足够；
- 重要数据要大一点；
- 不重要的信息可以放到详情页或弹窗里；
- 手机端不能出现大片拥挤表格。

### 2.4 设计重点

设计时优先考虑：

1. 用户一进来能不能看懂；
2. 项目状态是否一眼清楚；
3. 任务是谁负责是否明确；
4. 经费是否透明；
5. 成员贡献是否能被看见；
6. 重要提醒是否醒目；
7. 手机端是否方便查看。

## 3. 系统入口设计

平台分为两个入口。

### 3.1 内部管理系统

需要登录账号才能进入。

给团队成员、项目负责人、老师、管理员使用。

内部系统展示：

- 项目；
- 比赛；
- 任务；
- 人员；
- 经费；
- 文件；
- 贡献；
- 成员排序；
- 软著 / 专利申请；
- 敏感资料审批；
- 操作日志；
- 通知提醒。

### 3.2 公共展示主页

不需要登录也可以查看。

主要给老师、学院、合作方、新成员、外部人员看。

公共主页展示：

- 团队介绍；
- 获奖项目；
- 项目图片；
- 成员风采；
- 团队成果；
- 软著、专利、论文等已公开成果；
- 团队发展时间线。

公共主页不能展示：

- 经费明细；
- 身份证；
- 联系方式；
- 内部任务；
- 成员灵活工作时间；
- 异议反馈；
- 内部操作日志；
- 软著 / 专利申请过程中的敏感材料。

# 4. 内部系统整体布局

## 4.1 电脑端布局

电脑端建议采用：

```text
左侧导航栏 + 顶部状态栏 + 中间内容区
```

### 左侧导航栏

建议菜单：

```text
首页驾驶舱
项目管理
比赛管理
任务管理
人员管理
经费管理
文件资料
贡献与排序
成果与知识产权
敏感资料审批
导入导出
通知中心
操作日志
系统设置
```

其中普通成员看不到不属于自己权限的管理入口。

### 顶部状态栏

顶部建议展示：

- 当前登录人头像 / 姓名；
- 当前角色；
- 通知铃铛；
- 搜索框；
- 快速新建按钮；
- 退出登录。

### 中间内容区

根据不同菜单显示不同页面。

## 4.2 手机端布局

手机端不要照搬电脑端表格。

建议采用：

```text
顶部标题栏 + 底部常用菜单 + 卡片式内容
```

底部常用菜单建议：

```text
首页
项目
任务
通知
我的
```

手机端重点保证：

- 能看清项目；
- 能查任务；
- 能看通知；
- 能更新任务进度；
- 能填写灵活工作时间；
- 能提交贡献记录；
- 能查看经费总表；
- 能查看比赛节点。

复杂表格在手机端尽量变成卡片。

# 5. 内部首页：团队管理驾驶舱

这是最重要的页面。

用户登录后第一眼看到这里。

## 5.1 首页设计目标

首页要让大家一眼看清：

- 团队现在有多少项目；
- 哪些项目正在推进；
- 哪些比赛快截止；
- 哪些任务延期了；
- 哪些负责人没有更新；
- 经费现在用了多少；
- 最近谁完成了什么贡献；
- 哪些知识产权申请被退回或待修改。

## 5.2 首页建议布局

### 第一屏：核心数据卡片

顶部放 4 到 6 个数据卡片。

示例：

```text
当前项目数
进行中项目
本月比赛节点
待完成任务
总经费余额
待审核事项
```

每个卡片需要：

- 大数字；
- 简短说明；
- 小图标；
- 点击后能进入详情页。

### 第二屏：项目日历

展示所有项目的重要节点。

日历中可以显示：

- 比赛报名截止；
- 材料提交；
- 网评；
- 答辩；
- 校赛；
- 市赛；
- 省赛；
- 国赛；
- 项目结题；
- 知识产权申请截止；
- 退回修改截止。

设计要求：

- 日期上有颜色标记；
- 点击某一天能看到当天事项；
- 不同类型事件用不同颜色；
- 手机端可以切换成列表模式。

### 第三屏：项目时间线

展示项目从开始到结束的进度。

可以用横向时间线，也可以用项目列表 + 阶段标签。

每个项目显示：

- 项目名称；
- 当前阶段；
- 负责人；
- 进度条；
- 最近更新时间；
- 是否超期；
- 进入详情按钮。

阶段示例：

```text
立项
材料准备
网评审核
答辩准备
校赛
市赛
省赛
国赛
已获奖
已结项
```

### 第四屏：任务和提醒

展示：

- 我负责的任务；
- 即将截止任务；
- 已延期任务；
- 待我审核的贡献；
- 待我处理的知识产权退回；
- 待我审批的敏感资料申请。

任务卡片需要展示：

- 任务名称；
- 所属项目；
- 负责人；
- 截止时间；
- 当前状态；
- 操作按钮。

### 第五屏：经费总览

展示所有项目经费汇总。

内容包括：

- 项目名称；
- 奖金总额；
- 已使用金额；
- 剩余金额；
- 待报销金额；
- 经费状态。

可以用表格，也可以加统计图。

建议增加：

- 总奖金；
- 总支出；
- 总剩余；
- 支出类别占比图。

### 第六屏：成员闪光点动态

这是平台理念的重要体现。

展示最近成员的成果和努力，例如：

```text
某某完成了项目申报书
某某提交了个人比赛记录
某某完成了软著说明书初稿
某某完成了答辩 PPT
某某修正了科研处退回材料
某某上传了项目图片
某某完成了阶段任务
```

设计上可以做成动态流，类似“团队动态”。

目的不是监督，而是让每个人的努力被看见。

## 5.3 首页需要的状态颜色

| 状态 | 颜色 |
|---|---|
| 正常进行 | 蓝色 |
| 已完成 | 绿色 |
| 待审核 | 黄色 |
| 即将截止 | 橙色 |
| 已延期 | 红色 |
| 已暂停 | 灰色 |
| 已归档 | 深灰或浅蓝 |

# 6. 项目管理页面

## 6.1 项目列表页

展示所有项目。

每个项目卡片或表格需要显示：

- 项目名称；
- 项目负责人；
- 当前阶段；
- 项目成员数量；
- 关联比赛数量；
- 当前任务数；
- 经费余额；
- 最近更新时间；
- 状态标签；
- 进入详情按钮。

### 筛选条件

需要支持：

- 按项目阶段筛选；
- 按负责人筛选；
- 按比赛级别筛选；
- 按是否获奖筛选；
- 按是否延期筛选；
- 按年份筛选；
- 搜索项目名称。

### 两种展示模式

建议支持：

1. 表格模式；
2. 卡片模式。

手机端默认卡片模式。

## 6.2 项目详情页

项目详情页建议采用多个标签页。

标签页包括：

```text
项目概况
项目时间线
成员与分工
任务列表
比赛记录
经费明细
文件资料
贡献记录
成员排序
知识产权
操作日志
```

### 6.2.1 项目概况

展示：

- 项目名称；
- 项目简介；
- 项目负责人；
- 指导老师；
- 当前阶段；
- 开始时间；
- 预计结束时间；
- 当前进度；
- 项目状态；
- 最近更新；
- 项目图片；
- 项目成果。

页面顶部可以放一个进度条或阶段步骤条。

### 6.2.2 项目时间线

展示项目从立项到结项的完整过程。

时间线内容：

- 项目创建；
- 成员加入；
- 重要任务完成；
- 比赛报名；
- 材料提交；
- 网评；
- 答辩；
- 获奖；
- 经费使用；
- 软著 / 专利申请；
- 项目归档。

每个节点需要：

- 时间；
- 事件标题；
- 事件说明；
- 相关负责人；
- 附件或证明材料入口。

### 6.2.3 成员与分工

展示项目成员列表。

字段包括：

- 成员姓名；
- 项目角色；
- 当前任务；
- 贡献数量；
- 是否负责人；
- 是否核心成员；
- 是否已退出；
- 加入时间。

可以用成员卡片展示。

每个成员卡片上建议有：

- 姓名；
- 技能标签；
- 本项目贡献；
- 当前任务；
- 联系方式；
- 查看个人主页按钮。

### 6.2.4 任务列表

任务可以有两种视图：

1. 看板视图；
2. 表格视图。

看板分组：

```text
未开始
进行中
待审核
已完成
延期
```

任务卡片显示：

- 任务名；
- 负责人；
- 截止时间；
- 所属项目；
- 状态；
- 是否需要协助；
- 完成按钮。

### 6.2.5 比赛记录

展示项目参加过的比赛。

字段包括：

- 比赛名称；
- 比赛级别；
- 当前阶段；
- 报名时间；
- 材料提交时间；
- 网评时间；
- 答辩时间；
- 是否晋级；
- 是否获奖；
- 奖项等级；
- 复盘总结。

建议用时间线或表格展示。

### 6.2.6 经费明细

展示这个项目的全部经费记录。

顶部先显示汇总：

```text
奖金总额
已使用金额
剩余金额
待报销金额
```

下面展示明细表：

- 日期；
- 类型；
- 金额；
- 用途；
- 经办人；
- 票据；
- 备注。

票据图片可以点击预览。

### 6.2.7 文件资料

展示项目文件。

文件分类：

- 申报书；
- PPT；
- 答辩稿；
- 比赛通知；
- 证书；
- 软著材料；
- 专利材料；
- 经费票据；
- 项目图片；
- 其他。

每个文件显示：

- 文件名；
- 文件类型；
- 上传人；
- 上传时间；
- 版本；
- 权限级别；
- 下载按钮；
- 预览按钮。

### 6.2.8 贡献记录

展示项目成员贡献。

字段包括：

- 成员；
- 贡献类型；
- 贡献内容；
- 证明材料；
- 填写人；
- 审核状态；
- 审核人；
- 审核意见。

普通成员可以提交贡献记录。

项目负责人可以审核贡献记录。

### 6.2.9 成员排序

展示项目成员排序。

需要展示：

- 排名；
- 成员；
- 排名依据；
- 主要贡献；
- 是否老师确认；
- 是否有异议；
- 异议入口。

设计要求：

- 排序必须公开；
- 成员可以看到排名依据；
- 有异议时有明显入口；
- 老师确认后的排序要有“已确认”标识。

### 6.2.10 知识产权

展示该项目关联的软著和专利。

内容包括：

- 成果名称；
- 类型；
- 当前状态；
- 主导撰写人；
- 申请执行人；
- 退回次数；
- 当前责任人；
- 查看详情。

# 9. 人员管理页面

## 9.1 成员列表

展示所有成员。

字段：

- 姓名；
- 年级；
- 专业；
- 联系方式；
- 参与项目数；
- 当前任务数；
- 技能标签；
- 当前是否有空；
- 最近更新时间。

## 9.2 成员个人主页

每个成员都有个人主页。

展示：

- 基本信息；
- 联系方式；
- 技能标签；
- 参与项目；
- 当前任务；
- 完成任务；
- 贡献记录；
- 个人比赛；
- 个人项目；
- 软著 / 专利 / 论文参与；
- 成长时间线。

这个页面很重要，因为它体现“让每个人被看见”。

## 9.3 灵活工作时间页面

成员每半个月填写一次。

填写内容：

- 本半个月可投入时间；
- 每周大概可投入几小时；
- 是否能参加线下讨论；
- 是否能承担紧急任务；
- 是否任务饱和；
- 影响安排的事项。

团队总览页面要能看到每个人大概是否有空。

建议用：

- 日历；
- 表格；
- 成员卡片；
- 颜色状态。

状态示例：

```text
空闲
适中
较忙
非常忙
暂不可安排
```

# 10. 经费管理页面

## 10.1 经费总览

所有登录成员都可以看。

顶部展示：

- 总奖金；
- 总支出；
- 总剩余；
- 待报销总额。

下面展示所有项目经费表：

- 奖金总额；
- 已使用；
- 剩余；
- 待报销；
- 经费状态；
- 查看明细。

## 10.2 经费明细

# 12. 知识产权申请与责任追踪页面

这是一个重点模块。

## 12.1 模块目的

这个页面不是简单记录软著和专利，而是记录：

```text
谁写的
谁申请的
谁整理材料
谁提交科研处
谁被退回
谁修改
谁最终确认
```

目的是防止：

- 写材料的人不认真；
- 申请的人被迫反复修改；
- 责任不清；
- 成果贡献不公平；
- 挂名和甩锅。

## 12.2 菜单名称

建议菜单叫：

```text
成果与知识产权
```

里面可以有：

```text
申请总览
新建申请
待我处理
退回修改
成果归档
```

## 12.3 申请总览页

展示所有软著 / 专利申请。

字段：

- 成果名称；
- 类型；
- 关联项目；
- 当前状态；
- 主导撰写人；
- 申请执行人；
- 材料整理人；
- 退回次数；
- 当前责任人；
- 更新时间；
- 查看详情。

状态颜色：

| 状态 | 颜色 |
|---|---|
| 准备中 | 灰色 |
| 材料撰写中 | 蓝色 |
| 负责人审核中 | 黄色 |
| 老师确认中 | 黄色 |
| 科研处审核中 | 紫色 |
| 退回修改 | 红色 |
| 修改中 | 橙色 |
| 已受理 | 蓝绿色 |
| 已授权 / 已登记 | 绿色 |
| 已归档 | 深灰 |

## 12.4 新建申请页

表单包括：

- 成果名称；
- 成果类型；
- 关联项目；
- 主导撰写人；
- 协作撰写人；
- 申请执行人；
- 材料整理人；
- 项目负责人；
- 老师确认人；
- 申请说明；
- 预计提交时间。

表单要尽量分步骤，不要一页太长。

建议步骤：

```text
基础信息
责任分工
材料上传
确认提交
```

## 12.5 申请详情页

申请详情页建议用 8 个标签页：

```text
基础信息
责任分工
材料版本
申请流程
退回记录
贡献同步
异议反馈
操作日志
```

### 基础信息

展示成果的基本情况。

### 责任分工

重点展示：

- 主导撰写人；
- 协作撰写人；
- 申请执行人；
- 材料整理人；
- 项目负责人；
- 老师确认人。

每个人旁边要显示责任说明。

例如：

```text
主导撰写人：负责技术内容真实性和完整性
申请执行人：负责科研处提交和流程对接
材料整理人：负责身份证、申请表、代码、说明书等资料完整性
```

### 材料版本

展示所有材料和版本。

例如：

```text
v1 初稿
v2 负责人修改稿
v3 老师确认稿
v4 科研处退回修改稿
vFinal 最终提交版
```

每个版本显示：

- 文件名；
- 上传人；
- 上传时间；
- 修改说明；
- 是否最终版。

### 申请流程

用步骤条展示：

```text
准备中
材料撰写中
负责人审核
老师确认
科研处审核
退回修改
重新提交
已受理
已授权
已归档
```

### 退回记录

每次科研处退回都要记录。

展示：

- 退回时间；
- 退回原因；
- 责任类型；
- 责任人；
- 修改截止时间；
- 实际修改人；
- 修改结果；
- 证明材料。

退回记录要醒目，因为这是责任追踪的重点。

### 贡献同步

展示哪些申请工作已经同步为贡献记录。

例如：

- 软著说明书撰写；
- 源代码整理；
- 科研处退回修改；
- 专利交底书撰写；
- 成果归档。

### 异议反馈

项目成员可以提出异议。

展示：

- 异议人；
- 异议内容；
- 证明材料；
- 负责人意见；
- 老师意见；
- 处理状态。

### 操作日志

展示这个申请过程的所有关键操作。

## 12.6 待我处理页

展示当前登录用户需要处理的事项。

例如：

- 我需要写的材料；
- 我需要修改的退回；
- 我需要提交的申请；
- 我需要审核的申请；
- 我需要确认的排序；
- 我需要处理的异议；
- 我需要审批的敏感资料。

这个页面要做得很清楚，因为它可以帮助成员快速知道自己现在该干什么。

# 13. 敏感资料审批页面

## 13.1 模块目的

软著、专利申请可能需要身份证、手机号、地址、签字材料等。

这些资料不能直接公开。

必须：

```text
申请查看
审批通过
限时查看
记录每一次使用
```

## 13.2 页面包括

### 我的资料

成员可以查看自己已经录入的资料状态。

显示：

- 身份证号是否已录入；
- 身份证图片是否已上传；
- 手机号是否完善；
- 地址是否完善；
- 签字材料是否上传。

默认脱敏显示。

例如：

```text
身份证号：110***********1234
手机号：138****5678
```

### 申请查看资料

表单包括：

- 申请对象；
- 资料类型；
- 所属项目；
- 使用场景；
- 申请理由；
- 预计使用时间。

### 待我审批

审批人看到申请列表。

操作：

- 同意；
- 拒绝；
- 设置可查看时间；
- 填写审批意见。

### 限时查看页面

审批通过后，申请人在有效时间内可以查看。

页面要有明显倒计时：

```text
剩余可查看时间：28 分 35 秒
```

过期后自动不能查看。

# 21. 给设计同学的一句话

这个平台不是普通后台管理系统。

它的核心不是“管人”，而是：

> 让团队信息更透明，让任务分工更清楚，让经费使用更公开，让每个人的努力和贡献都能被看见。

所以页面设计不要只做成冷冰冰的表格，要有团队感、成长感和成果展示感。

# 23. 最终希望达到的页面效果

设计完成后，一个新成员进入系统应该能很快明白：

1. 团队现在有哪些项目；
2. 每个项目进行到哪里；
3. 自己可以参与什么；
4. 谁负责什么任务；
5. 哪些比赛快截止；
6. 经费是怎么使用的；
7. 谁做出了什么贡献；
8. 自己的个人项目和成果也可以被记录；
9. 团队不是只看资历，而是看实际贡献；
10. 每个人都有机会被看见。
