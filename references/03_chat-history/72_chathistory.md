## 1. 项目背景

团队当前项目和比赛较多，成员超过 50 人，人员变动频繁。现有腾讯共享文档难以长期维护项目、比赛、任务、经费、文件、贡献、排序和成果申请过程。因此计划建设一个可部署到老师或团队服务器上的网页系统。

系统定位：

```text
项目管理系统 + 成员管理系统 + 比赛管理系统 + 经费台账系统
+ 文件资料系统 + 贡献认定与排序系统
+ 知识产权申请与责任追踪系统 + 敏感资料审批系统
+ 团队主页 / 公共展示系统

核心理念：

让团队信息更透明；
让任务分工更清楚；
让经费使用更公开；
让每个人的努力和贡献都能被看见；
让项目成果能够长期沉淀为团队资产。
2. 已确认的核心规则
2.1 公开透明

对所有登录成员公开：

经费明细；
经费票据图片；
项目进度、比赛阶段、项目时间线；
任务完成情况；
成员联系方式；
成员灵活工作时间；
成员技能标签；
项目贡献记录；
成员排序。

公共展示页无需登录，但不能展示：

经费明细；
身份证等敏感资料；
联系方式；
内部任务；
灵活工作时间；
异议反馈；
操作日志；
软著 / 专利申请过程中的敏感材料。
2.2 时间与提醒
成员灵活工作时间每半个月填写一次。
项目负责人每 1.5 周更新一次项目，系统按 11 天判断。
任务延期 1.5 天后提醒，即截止时间后 36 小时。
第一阶段提醒方式为站内信 + 邮件。
暂时不接飞书，但预留飞书、企业微信、QQ群机器人、Webhook 等接口。
2.3 贡献与排序
所有项目成员都可以填写贡献记录。
贡献记录需要项目负责人审核。
成员排序由项目负责人生成草稿，老师最终确认。
成员可提出异议，项目负责人初审，老师终审。
排序优先依据本项目真实贡献，而不是资历、挂名或历史成果。
新人贡献多也能排在前面。
同一个人在不同项目中的贡献要分别判断。

排序原则：

项目内实际贡献 > 项目关键资源贡献 > 项目管理责任 > 团队历史贡献 > 加入时间
2.4 敏感资料

身份证号、身份证图片、手机号、地址、签字材料等敏感资料默认脱敏显示。查看明文必须提交申请，审批通过后限时查看，每次查看、下载、导出都必须写操作日志。上线真实资料前必须先用模拟数据验证完整流程。

3. 技术栈与架构

建议技术路线：

前端：Vue 3 + TypeScript + Element Plus
后端：Django REST Framework
数据库：PostgreSQL
异步任务：Celery + Redis
部署：Docker Compose + Nginx
导入导出：Excel / Word / PDF

Django 作为主后端；Vue 负责内部后台、驾驶舱、移动端和公共展示；PostgreSQL 负责长期数据沉淀；Celery + Redis 负责定时提醒；Nginx 负责静态资源和 API 转发；FastAPI 仅作为未来 AI / 数据分析服务预留。

5. 核心业务模块需求
5.1 首页驾驶舱

首页需要展示当前项目数、进行中项目数、本月比赛节点、待完成任务、延期任务、总经费余额、待审核事项、成员灵活工作时间、最近贡献动态、知识产权申请状态、待我处理事项、最近通知、风险提醒。

展示形式建议包括数据卡片、项目日历、时间线、任务提醒、经费图表、团队动态流和风险提醒列表。

5.2 项目管理

项目列表展示项目名称、负责人、当前阶段、成员数量、关联比赛、任务数量、经费余额、最近更新时间和状态。

项目详情页建议包含：

项目概况
项目时间线
成员与分工
任务列表
比赛记录
经费明细
文件资料
贡献记录
成员排序
知识产权
操作日志

项目生命周期：

项目立项
→ 确定负责人和成员
→ 建立项目档案
→ 录入项目计划
→ 材料准备与任务推进
→ 参加比赛或项目评审
→ 更新项目进度
→ 记录成果和奖项
→ 整理经费和资料
→ 项目结项
→ 沉淀为历史项目
5.3 比赛管理

管理比赛名称、类型、级别、主办单位、报名时间、提交时间、网评、答辩、关联项目、阶段、晋级、获奖、复盘等。

比赛流程：

录入比赛信息
→ 关联参赛项目
→ 设置比赛阶段
→ 报名准备
→ 材料提交
→ 网评
→ 答辩
→ 校赛 / 市赛 / 省赛 / 国赛
→ 结果记录
→ 同步项目档案
→ 沉淀比赛经验
5.4 任务管理

任务字段包括任务名称、所属项目、负责人、协作成员、说明、截止时间、状态、完成情况、延期原因、审核人和附件。

任务状态：

未开始
进行中
待审核
已完成
延期
暂停
取消
需要协助

任务延期提醒：截止时间 + 36 小时后触发。

5.5 人员与灵活工时

成员信息包括姓名、年级、专业、联系方式、账号状态、参与项目、当前任务、角色、技能标签、灵活工作时间和贡献记录。

成员角色：

管理员
老师
项目负责人
核心成员
普通成员
指导老师
已退出成员
外部协作成员
敏感资料审批人

技能标签示例：前端、后端、UI、文档、PPT、答辩、绘图、视频、数据整理、算法、实验、机械设计、财务整理、比赛申报、项目统筹。

灵活工作时间每半个月填写一次，记录可投入时间、每周小时数、是否能线下讨论、是否能紧急任务、任务是否饱和以及考试课程实习等影响。

5.6 经费管理

经费明细和票据对所有登录成员公开。经费总表展示项目名称、奖金总额、其他收入、已使用金额、剩余金额、待报销金额、经费状态和更新时间。单项目经费明细展示收入、支出、报销、票据、用途、经办人、审核人和备注。

5.7 文件资料

文件权限分为普通文件、内部文件、敏感文件。普通文件登录成员可见，内部文件项目成员可见，敏感文件需审批后限时查看。文件类型包括申报书、PPT、答辩稿、比赛通知、证书、软著材料、专利材料、经费票据、项目图片等。

5.8 贡献、排序与异议

贡献流程：

成员填写贡献
→ 项目负责人审核
→ 审核通过后进入贡献档案
→ 成为排序依据

排序流程：

项目负责人生成排序草稿
→ 调整并说明依据
→ 老师最终确认
→ 排序公开
→ 成员提出异议
→ 项目负责人初审
→ 老师终审

排序依据包括贡献记录、任务完成情况、知识产权申请贡献、软著/专利退回修改贡献、申请执行贡献和负责人调整说明。

成果类型包括：

软件著作权
发明专利
实用新型
外观设计
论文
作品著作权
其他成果

状态包括：

准备中
材料撰写中
负责人审核中
老师确认中
科研处审核中
退回修改

已重新提交
已受理
已授权 / 登记
已归档
暂停
终止

6.2 责任分工
主导撰写人：负责成果内容真实性、完整性、技术描述质量。
协作撰写人：负责自己部分。
申请执行人：负责科研处对接、系统提交、时间节点。
材料整理人：负责身份证、申请表、代码、说明书、签字材料等完整性。
项目负责人：负责初审。
老师：负责最终确认。
修改责任人：负责某次退回问题修改。
归档责任人：负责证书和最终材料归档。
6.3 申请流程
创建申请档案
→ 关联项目
→ 确认成果类型
→ 确认撰写人 / 执行人 / 整理人
→ 上传材料
→ 负责人审核
→ 老师确认
→ 提交科研处 / 平台
→ 记录退回原因
→ 分配修改责任人
→ 修改后重新提交
→ 受理 / 授权 / 登记
→ 上传证书和最终材料
→ 归档
→ 同步贡献
6.4 模块联动

知识产权模块联动贡献记录、成员排序、异议反馈、敏感资料审批、操作日志、通知中心。

专利撰写贡献
专利申请执行贡献
专利退回修改贡献

联动规则：

→ 系统生成待审核贡献记录
→ 项目负责人审核
