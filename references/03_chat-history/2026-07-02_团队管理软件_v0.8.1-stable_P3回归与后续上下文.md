## 4. P0/P1/P2 修复过程摘要

### 4.1 登录问题

曾出现：

```text
django.urls.exceptions.NoReverseMatch: 'djdt' is not a registered namespace
```

根因：`django-debug-toolbar` 中间件启用，但 `urls.py` 没有注册 `__debug__/` 路由。

修复方向：在 DEBUG 且安装 debug_toolbar 时注册：

```python
if settings.DEBUG and 'debug_toolbar' in settings.INSTALLED_APPS:
    urlpatterns += [
        path('__debug__/', include('debug_toolbar.urls')),
    ]
```

随后登录成功但不跳转的问题，根因是后端返回：

```text
data.token.access
data.token.refresh
user.global_role
```

但前端曾读取：

```text
result.access
result.refresh
user.role
```

已修复为读取 `result.token.access`、`result.token.refresh` 和 `user.global_role`。


这个仓库是之前的旧项目 / 实验项目，不是当前新主线。

当时使用 MinIO 可能是为了：

1. 测试对象存储；
2. 测试预签 URL；
3. 测试文件权限中心；
4. 模拟 OSS / S3 类文件管理。

当前新项目应该没有继续使用 MinIO。当前文件模块更可能是 Django 后端文件上传、权限控制、敏感资料审批和操作日志。

可以在项目根目录用以下命令确认是否还使用 MinIO：

```powershell
Get-ChildItem -Recurse -File | Select-String -Pattern "minio|MINIO|s3|S3|boto3|django-storages|AWS_ACCESS_KEY|AWS_SECRET|STORAGE_ENDPOINT"
```

后端依赖检查：

```powershell
cd backend
pip freeze | findstr /i "minio boto3 storages s3"
```

如果没有搜索到相关关键词，基本可以确认当前新项目没有使用 MinIO。
