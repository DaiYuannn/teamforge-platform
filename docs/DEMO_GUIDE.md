# 团队管理软件演示指南

> 适用版本：v2.1.0
> 发布日期：2026-07-27
> 演示数据入口：`python manage.py seed_demo_data --clean --force`

本指南面向演示、验收和上线前试运行。演示环境只使用模拟账号、模拟票据和模拟敏感资料，禁止在完成权限与恢复演练前导入真实成员证件或财务资料。

## 1. 启动环境

### 1.1 依赖

- Python 3.10+
- Node.js 18+
- PostgreSQL 14+
- Redis 7+
- Tesseract OCR（容器镜像已安装中文语言包）

PDF 由 ReportLab 生成，不依赖 WeasyPrint 或 GTK。

### 1.2 后端

```bash
cd backend
pip install -r requirements/dev.txt
python manage.py migrate
python manage.py seed_demo_data --clean --force
python manage.py runserver
```

升级既有环境时确认已应用 `users.0007_userpreference_schedule_end_and_more`；该迁移保存每个账户的明暗模式和定时范围。

后端默认地址：`http://127.0.0.1:8000`。

### 1.3 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认地址：`http://127.0.0.1:3000`。

### 1.4 定时任务

本地演示定时提醒和定时报表时，同时启动 Worker 与 Beat：

```bash
cd backend
celery -A config worker -l info
celery -A config beat -l info
```

Docker 生产编排默认启动这两个服务，无需额外 profile。

## 4. 推荐验收顺序

### 4.1 账户偏好与隔离

1. 使用 `admin@demo.com` 登录，确认主色和明暗模式为管理员保存的设置。
2. 进入 `/user/preference`，依次预览浅色、深色和跟随系统；确认页面、弹窗、表格及图表同步切换且文字可读。
3. 选择定时模式并设置跨午夜时段（例如 `19:00` 至 `07:00`），保存后刷新页面，确认设置仍由服务器恢复。
4. 修改主色、默认着陆页、每页条数、默认数据范围、侧栏状态、常用入口、菜单顺序和通知偏好。
5. 退出并登录 `teacher1@demo.com`，确认主色、明暗模式和布局自动切换为老师账户自己的设置；退出后恢复跟随系统。
6. 检查通知铃铛中没有上一账户的数据，默认着陆页按新账户设置跳转。

偏好保存在服务器，不依赖当前浏览器的本地缓存。

### 4.2 项目、比赛和时间线

1. 进入 `/projects`，查看 24 个项目及成员、阶段和负责人更新。
2. 打开项目详情，推进阶段并填写进度；确认时间线产生“阶段变更”。
3. 新建、完成任务并上传文件；确认出现“任务创建”“任务完成”“文件上传”。
4. 进入 `/competitions`，查看报名、材料、网评、答辩和结果节点。
5. 在时间线多选“任务”“比赛”“贡献”等分类，确认筛选结果没有英文事件代码。
6. 进入 `/dashboard/calendar`，确认任务截止、项目启动、项目结束、经费支出均显示中文标签。

### 4.3 成员、半月工时与变动

1. 进入 `/members` 和 `/team`，查看 50 人以上团队的联系方式、技能和参与项目。
2. 普通成员进入 `/members/schedule`，填写当月 1-15 日或 16-月末的灵活工作时间。
3. 负责人进入 `/members/team-schedule`，查看团队可用时间、饱和状态和紧急任务能力。
4. 演示成员退出、负责人交接和交接说明，确认历史成员关系仍可追溯。

### 4.4 贡献、排序与异议

1. 项目成员进入 `/contributions` 提交本项目真实贡献及证明文件。
2. 项目负责人进入 `/contributions/pending` 审核贡献。
3. 负责人依据审核通过的贡献生成排序草案。
4. 老师执行最终确认后向项目成员公开排序。
5. 成员提交异议，负责人初审，老师终审；检查所有意见和调整快照均被保留。

排序以当前项目贡献为核心，不使用跨项目总分直接替代本项目判断。

### 4.5 经费与票据 OCR

1. 进入 `/finance`，查看预算、收入、支出、报销状态和票据。
2. 点击“票据 OCR”，上传清晰的 PNG/JPEG/PDF 模拟票据。
3. 检查金额、日期、票据号、商户等结构化结果。
4. 人工修正低置信度字段后保存支出和票据。
5. 模拟票据上传失败，确认不会留下重复支出或无法继续使用的半成品。

OCR 结果必须人工复核，识别结果不能直接作为财务凭证。

### 4.6 文件和知识产权

1. 进入 `/files`，创建项目文件夹，给文件分配标签并在同一项目内移动文件。
2. 分别预览或下载演示 PDF、Word、Excel 和 PPT 文件，确认 Office 预览只提取有界只读内容。
3. 上传新版本并恢复历史版本，确认文件版本和审计记录同步更新。
4. 创建并撤销非敏感文件分享；确认敏感文件不能创建公开分享。
5. 删除文件后进入回收站验证恢复，并按角色检查永久删除权限。
6. 进入 `/intellectual-property`，演示材料撰写、负责人审核、老师确认、退回修改、受理、授权和归档。
7. 检查知识产权节点进入项目时间线，最终证书是独立 PDF 文件。

### 4.7 敏感资料

1. 普通成员进入 `/sensitive`，默认只能看到脱敏内容。
2. 提交查看申请并说明用途。
3. 使用 `approver@demo.com` 在 `/sensitive/pending` 审批并设置有效期。
4. 切回申请账号，在有效期内查看或下载；过期后再次访问应被拒绝。
5. 在 `/audit/logs` 核对申请、审批、查看和下载记录。

### 4.8 实时通知

1. 同时打开负责人和成员两个会话。
2. 在一个会话创建任务、贡献审核或报表执行结果。
3. 另一个会话应在不刷新页面的情况下收到站内通知。
4. 点击通知直接进入关联项目、任务、比赛、经费或报表页面。
5. 一个终端标记已读后，另一个终端应同步更新；断开 Redis 后恢复连接，数据库补偿不能漏掉通知。

### 4.9 定时报表

1. 进入 `/reports`，查看每日、每周和每月计划。
2. 下载已有 XLSX、DOCX、PDF 执行文件。
3. 创建计划，设置数据源、频率、时间、格式和接收人。
4. 创建者、老师或管理员可编辑、启停、立即运行和删除；仅接收人只能查看和下载。
5. 立即运行后检查执行状态、站内通知和文件下载。

### 4.10 演示备份恢复

1. 管理员进入 `/admin/backups` 创建备份包。
2. 下载 ZIP，核对 `manifest.json`、业务快照、附件和 SHA-256 清单。
3. 修改一条演示业务数据，再选择刚才的包执行恢复。
4. 系统应先生成回滚包，然后恢复所选包当时的数据和附件。
5. 恢复后本地登录状态被清除，需要重新登录。
6. 再选择回滚包恢复，确认可以回到恢复操作前的状态。

该入口只管理 `seed_demo_data` 所有的演示数据，不替代生产数据库和媒体灾难恢复。生产恢复流程见 `docs/BACKUP_GUIDE.md`。

### 4.11 v2.1 协作、分析与平台工作台

1. 从任务列表进入 `/tasks/:id/collaboration`，检查子任务、依赖、评论、回复和成员提及。
2. 从项目详情进入 `/projects/:id/operations`，检查里程碑、风险、讨论、知识、复盘、模板和四类智能分析。
3. 进入 `/analytics-studio`，检查自定义看板、报表生成、智能周报和 Markdown 导出。
4. 进入 `/admin/platform-capabilities`，分别使用管理员和普通成员确认可写操作会按角色降级。
5. 使用系统管理员进入 `/admin/engineering`，检查真实性能采样、OpenAPI 索引和质量门禁；普通成员不得访问系统元数据。
6. 在桌面与移动视口重复以上路径，检查无空白页、重叠、横向溢出或桌面侧栏误显示。

## 6. 常见问题

### 前端端口是什么？

Vite 默认使用 `3000`，后端默认使用 `8000`。

### PDF 是否需要 GTK？

不需要。当前 PDF 使用 ReportLab 和 CID 中文字体。

### 为什么没有收到定时提醒？

检查 Celery Worker、Beat 和 Redis。实时站内通知还需检查 SSE 请求与 Nginx 的 `X-Accel-Buffering` 配置。

### 为什么 OCR 识别不准？

优先使用清晰、方向正确、无遮挡的原图。系统会返回置信度并要求人工确认；过大、像素异常或处理超时的文件会被拒绝。

### 可以直接用演示备份恢复生产数据吗？

不可以。演示备份只处理带有明确演示所有权标记的数据。生产数据库、媒体文件和密钥必须按生产备份指南单独恢复。
