## 1. 如何启动项目

### 1.1 环境要求

- Python 3.10+
- Node.js 18+
- PostgreSQL 14+（开发默认，支持环境变量覆盖）
- （可选）GTK 运行时：用于 PDF 导出（WeasyPrint 依赖）

### 1.2 启动后端

```bash
cd backend
pip install -r requirements/dev.txt
python manage.py migrate
python manage.py runserver
```

后端默认运行在 `http://127.0.0.1:8000`。

### 1.3 启动前端

```bash
cd frontend
npm install
npm run dev
```

前端默认运行在 `http://127.0.0.1:5173`，浏览器打开后自动跳转登录页。

### 1.4 生成演示数据

系统提供演示数据生成命令，可一键创建演示账号、项目、任务、经费、贡献等全套数据：

```bash
python manage.py seed_demo_data --clean --force
```

| 参数 | 说明 |
|------|------|
| --clean | 清空已有的演示数据后再生成 |
| --force | 跳过交互确认，强制执行 |

> 提示：首次演示前务必执行一次，确保数据库中有完整的演示场景数据。

### 1.5（可选）启动 Celery

通知邮件、异步任务依赖 Celery，如需演示通知推送功能：

```bash
cd backend
celery -A config worker -l info
```

若未启动 Celery，站内通知仍可正常生成，仅邮件推送不工作。

## 3. 推荐演示顺序

1. 用管理员登录 → 首页驾驶舱 → 项目管理 → 经费管理 → 任务管理
2. 切换项目负责人 → 创建贡献 → 审核贡献 → 生成排序
3. 切换老师 → 确认排序 → 处理异议
4. 演示知识产权 → 退回修改 → 贡献同步
5. 演示敏感资料 → 申请查看 → 审批 → 限时查看
6. 演示导出 → Excel 导出

> 每一步切换账号时，建议先退出当前账号（右上角头像 → 退出登录），再使用新账号登录，以清晰展示权限边界。

## 4. 管理员视角：首页驾驶舱与基础管理

## 5. 项目管理演示

### 5.1 项目列表

- 操作路径：`/projects`
- 预期效果：
  - 卡片/列表展示所有项目，含项目编号、负责人、当前阶段、状态、优先级
  - 支持按状态、优先级筛选与关键词搜索
  - 管理员/老师可见「新建项目」按钮

### 5.2 创建项目

- 操作路径：`/projects` → 点击「新建项目」
- 操作账号：admin / teacher / leader
- 操作步骤：
  1. 填写项目名称、编号、负责人、优先级、起止时间、简介
  2. 提交后返回项目列表，新项目出现在列表顶部
- 预期效果：项目创建成功，默认进入第 1 阶段，状态为「进行中」

### 5.3 项目详情与阶段流转

- 操作路径：`/projects/:id`
- 操作账号：项目负责人（leader1@demo.com）
- 操作步骤：
  1. 进入项目详情页，查看项目基本信息、成员列表、阶段进度条
  2. 点击「推进阶段」按钮，填写备注后推进至下一阶段
  3. 点击「负责人打卡」，填写本周进展说明
- 预期效果：
  - 阶段进度条更新，阶段变更记录到日志
  - 仅项目负责人可执行阶段流转与打卡操作，普通成员看不到操作按钮

### 5.4 项目成员管理

- 操作路径：`/projects/:id` → 成员管理区
- 操作步骤：负责人可添加/移除项目成员，设置成员在项目中的角色（核心成员/参与者）
- 预期效果：成员列表实时更新，新成员可在「我的贡献」中为该项目填写贡献

## 8. 贡献与排序演示

### 8.1 填写贡献（项目成员）

- 操作路径：`/contributions` → 「填写贡献」
- 操作账号：普通成员（member1@demo.com）
- 操作步骤：
  1. 选择所属项目，填写贡献类型、贡献内容、权重、统计周期
  2. 提交后贡献状态为「待审核」
- 预期效果：贡献记录出现在「我的贡献」列表，状态显示「待审核」

### 8.2 审核贡献（项目负责人）

- 操作路径：`/contributions/pending`
- 操作账号：项目负责人（leader1@demo.com）
- 操作步骤：
  1. 在「待我审核」中查看待审核贡献
  2. 点击「审核」，选择通过/驳回，填写审核意见，可调整权重
- 预期效果：贡献状态变为「已通过」或「已驳回」，成员可在「我的贡献」查看审核结果

### 8.3 生成排序（项目负责人）

- 操作路径：`/contributions` → 「生成排序」
- 操作账号：项目负责人（leader1@demo.com）
- 操作步骤：
  1. 选择项目与统计周期，点击「生成排序草案」
  2. 系统根据贡献权重自动生成成员排名草案
  3. 负责人可手动调整排名与总分
- 预期效果：生成排名草案，状态为「草案」，仅负责人/老师可见，普通成员不可见

### 8.4 确认排序（老师）

- 操作路径：`/contributions` → 「确认排序」
- 操作账号：老师（teacher1@demo.com）
- 操作步骤：
  1. 老师查看草案，点击「确认排序」
  2. 确认后排名状态变为「已确认」，对全员公开
- 预期效果：排名公开，普通成员可在贡献列表看到最终排名

### 8.5 处理异议

- 操作账号：普通成员（member1@demo.com）→ 负责人 → 老师
- 操作步骤：
  1. 普通成员对已公开排名点击「提交异议」，填写异议内容
  2. 切换负责人账号，在异议列表点击「初审」，填写负责人意见
  3. 切换老师账号，点击「终审」，填写老师意见并给出最终结果（通过/驳回）
- 预期效果：异议状态流转「待处理 → 已初审 → 已通过/已驳回」，全程可追溯

## 9. 知识产权演示

### 9.1 创建知识产权申请

- 操作路径：`/intellectual-property` → 「新建申请」
- 操作账号：项目负责人（leader1@demo.com）/ 老师 / 管理员
- 操作步骤：
  1. 填写成果名称、类型（发明专利/实用新型/软件著作权/论文）、关联项目、主导撰写人、申请执行人
  2. 提交后申请状态为「材料撰写中」
- 预期效果：申请出现在知识产权列表，进入「待我处理」队列

### 9.2 状态流转与退回修改

- 操作路径：`/intellectual-property/:id`
- 操作步骤：
  1. 主导撰写人完成材料后，流转状态至「负责人审核」→「老师确认」→「科研处审核」
  2. 在科研处审核环节，创建「退回记录」，填写退回原因与修改截止日期
  3. 申请状态变为「退回修改中」
  4. 责任人完成修改后，在退回记录点击「完成修改」，填写修改说明
  5. 状态恢复流转
- 预期效果：
  - 退回记录可在详情页查看完整修改历程
  - 状态流转全程记录到操作日志

### 9.3 贡献同步与成果归档

- 操作步骤：
  1. 申请通过后，项目负责人点击「同步贡献」
  2. 系统根据责任分工自动生成项目成员的贡献记录
  3. 老师点击「成果归档」，申请状态变为「已归档」
- 预期效果：
  - 同步贡献返回同步条数，贡献列表出现对应记录
  - 归档后申请不可再修改

### 9.4 待办与异议处理

- 操作路径：`/intellectual-property/todo`
- 预期效果：根据当前用户角色显示待其处理的申请（撰写人看撰写中、负责人看审核中、老师看确认中）
- 异议处理：项目成员可对责任分工提交异议，负责人初审、老师终审，流程同贡献异议

## 10. 敏感资料演示

- 操作路径：`/sensitive`
- 操作账号：任意已登录用户
- 预期效果：
  - 敏感资料中心展示所有资料（脱敏，如身份证号显示为 `330***********1234`）

### 10.2 申请查看明文

- 操作路径：`/sensitive` → 资料条目 → 「申请查看」
- 操作账号：普通成员（member1@demo.com）
- 操作步骤：
  1. 选择要查看的敏感资料，填写查看原因
  2. 提交后申请状态为「待审批」
  3. 在 `/sensitive/requests` 可查看自己的申请记录
- 预期效果：申请提交成功，等待审批人处理

### 10.3 审批申请

- 操作路径：`/sensitive/pending`
- 操作账号：敏感审批人（approver@demo.com）
- 操作步骤：
  1. 在「待我审批」中查看待审批申请
  2. 点击「通过」，可设置有效时长（默认 1 小时），填写审批意见
  3. 或点击「驳回」并填写驳回理由
- 预期效果：审批通过后申请状态变为「已通过」，设置过期时间

### 10.4 限时查看明文

- 操作账号：普通成员（member1@demo.com）
- 操作步骤：
  1. 在 `/sensitive/requests` 找到已通过的申请
  2. 在有效期内点击「查看明文」
- 预期效果：
  - 弹窗展示明文内容，并提示「请在有效期内使用并注意明文保密」
  - 超过有效期后查看返回权限不足
  - 每次查看均写入操作日志，可在「操作日志」中追溯

## 12. 常见问题

### Q1：忘记密码怎么办？

演示账号密码见本文档「测试账号列表」。若自行创建的账号忘记密码，可由系统管理员在「用户管理」页面重置密码；或通过后端命令重置：

```bash
cd backend
python manage.py shell
>>> from apps.users.models import User
>>> u = User.objects.get(email='xxx@demo.com')
>>> u.set_password('newpassword')
>>> u.save()
```

### Q2：Celery 未启动，提醒不工作？

站内通知不依赖 Celery，可正常生成与查看。但邮件通知、异步推送任务需要 Celery 支持。如需演示邮件推送，请启动 Celery Worker：

```bash
cd backend
celery -A config worker -l info
```

同时检查 `.env` 中的 SMTP 邮件配置是否正确。

### Q3：PDF 导出需要 GTK？

是的。PDF 导出基于 WeasyPrint，依赖 GTK 运行时环境。若未安装 GTK，调用 PDF 导出会返回错误码 `1005`（运行时依赖不可用）。

解决方法：
- Windows：下载安装 GTK3 Runtime（https://github.com/tschoonj/GTK-for-Windows-Runtime-Environment-Installer）
- 安装后重启终端与服务，再次尝试导出
- 若暂无 GTK 环境，可改用 Word（docx）格式导出作为替代

### Q4：端口被占用？

后端默认端口 8000，前端默认端口 5173。若启动时报端口占用错误：

```bash
# 查找占用端口的进程（Windows）
netstat -ano | findstr :8000
taskkill /PID <进程ID> /F

# 或指定其他端口启动
python manage.py runserver 8001          # 后端
npm run dev -- --port 5174               # 前端
```

> 注意：更换前端端口后，需同步修改后端 CORS 配置与前端的 API 代理地址。

### Q5：演示数据生成失败？

- 确保已执行 `python manage.py migrate` 完成数据库迁移
- 使用 `--clean --force` 参数先清空再生成
- 若仍失败，检查是否有外键约束冲突，可删除 `db.sqlite3` 后重新迁移并生成

### Q6：切换账号后数据未刷新？

退出登录后建议清除浏览器本地存储（LocalStorage 中的 token），或使用浏览器无痕模式分别登录不同账号，避免 token 缓存导致权限错乱。

## 15. 如何重新生成演示数据

如果演示数据被修改或需要恢复初始状态：

```bash
# 在项目 backend 目录下执行
python manage.py seed_demo_data --clean --force
```

参数说明：
- `--clean`：先清空已有的演示数据（不会删除管理员账号和真实数据）
- `--force`：跳过确认提示，直接执行

Docker 部署环境：

```bash
docker compose -f deploy/docker-compose.prod.yml exec backend python manage.py seed_demo_data --clean --force
```

> 注意：重新生成数据后，敏感资料的查看申请会重置，需重新走审批流程演示。

## 16. 演示时敏感数据注意事项

### 绝对不要在演示中使用的信息

| 禁止使用 | 替代方案 |
|----------|----------|
| 真实身份证号码 | 使用演示脚本生成的模拟号码（110101 开头） |
| 真实手机号码 | 使用 1380000XXXX 格式的模拟号码 |
| 真实银行卡号 | 不输入，演示时使用脱敏显示 |
| 真实家庭住址 | 使用"北京市海淀区XX路XX号"等模拟地址 |

### 演示脚本已生成的模拟数据

演示数据中所有敏感资料均使用模拟数据：
- 身份证号：以 `110101` 开头，后接随机出生日期与顺序号
- 手机号：以 `1380000` 开头
- 地址：使用通用的"XX省XX市XX区"格式

### 演示时的话术建议

> "系统中所有身份证号等敏感信息均使用 Fernet 对称加密存储，列表页仅显示脱敏信息（如 110101\*\*\*\*），查看明文需提交申请并经审批人批准，批准后限时查看（默认 30 分钟），每次查看均记录操作日志。"

## 17. 演示结束后如何清理数据

### 方法一：重新生成演示数据（推荐）

```bash
python manage.py seed_demo_data --clean --force
```

这会清空所有演示数据并重新生成，恢复到初始状态。

### 方法二：清空全部数据（谨慎）

```bash
# 进入 Django shell
python manage.py shell

# 执行以下 Python 代码清空全部业务数据
from django.contrib.auth import get_user_model
User = get_user_model()
# 保留 admin 账号
User.objects.exclude(email='admin@demo.com').delete()

# 清空各模块数据
from apps.projects.models import Project, ProjectMember, Task
from apps.finance.models import FinanceBudget, FinanceExpense, FinanceReceipt
from apps.contributions.models import Contribution, MemberRanking, RankingObjection
from apps.intellectual_property.models import IPApplication
from apps.sensitive.models import SensitiveData, SensitiveAccessRequest
from apps.notifications.models import Notification
from apps.audit.models import OperationLog

for model in [OperationLog, Notification, SensitiveAccessRequest, SensitiveData,
              IPApplication, RankingObjection, MemberRanking, Contribution,
              FinanceReceipt, FinanceExpense, FinanceBudget, Task, ProjectMember, Project]:
    model.objects.all().delete()
    print(f'{model.__name__} cleared')
exit()
```

### 方法三：Docker 环境重置

```bash
# 停止服务并删除数据卷（彻底重置）
docker compose -f deploy/docker-compose.prod.yml down -v

# 重新启动并初始化
docker compose -f deploy/docker-compose.prod.yml up -d --build

# 生成演示数据
docker compose -f deploy/docker-compose.prod.yml exec backend python manage.py seed_demo_data --clean --force
```
